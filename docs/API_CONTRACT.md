# 위젯 일정 조회 및 기기 인증 API 계약

운영 서버 기준 주소는 `https://sjows.vercel.app`이다. 위젯은 Rust 계층에서만 HTTPS 통신과 인증을
처리하며 Neon 또는 SJOWS 데이터베이스에 직접 연결하지 않는다.

## 기기 연결

1. `POST /api/widget/device/start`에 기기 이름을 보내 연결 코드와 브라우저 승인 주소를 받는다.
2. 위젯은 코드가 포함된 승인 주소를 기본 브라우저로 연다. 서버가 코드를 자동 확인해 기기 이름과 코드를 표시하면 교직원은 **승인하기** 한 번으로 연결을 허용한다. 사용자가 승인 주소에 직접 들어온 경우에만 코드를 수동 입력한다.
3. `POST /api/widget/device/token`을 서버가 지정한 간격으로 폴링한다.
4. 승인 뒤 받은 액세스 토큰으로 일정 API를 호출하고 회전형 갱신 토큰으로 인증을 갱신한다.
5. 로그아웃 때 `POST /api/widget/device/revoke`를 호출하고 로컬 자격 증명을 삭제한다.

갱신 토큰은 Windows 자격 증명 저장소에만 보관한다. 액세스·갱신 토큰은 React 상태,
`localStorage`, 설정 파일이나 로그에 기록하지 않는다.

## 일정 조회

`GET /api/widget/calendar?from=2026-09-08&to=2026-09-14`

- 인증: 기기에 묶인 읽기 전용 자격 증명. 브라우저 로그인 HTML과 리디렉션을 반환하지 않는다.
- `from`, `to`: Asia/Seoul의 `YYYY-MM-DD`, 포함 범위이며 최대 93일이다.
- 성공: `200`과 `{ schemaVersion, timezone: "Asia/Seoul", generatedAt, events }` JSON을 반환한다.
- 오류: 잘못된 요청 `400`, 인증 만료 `401`, 권한 없음 `403`, 일정 조회 실패 `503`.
- `date`와 `endDate`는 포함 범위이며, `allDay`일 때 시간은 `null`이다.

서버는 기본 일정과 DB 수정값을 다음 순서로 결합한다: 기본 ID를 구성하고, 같은 ID의 DB 값으로 전체 대체하고, DB 전용 항목을 추가하고, `deleted` 항목을 제외한다. 시작일과 종료일 모두 고려해 요청 범위와 겹치는 일정만 반환한다. DB 실패 시 기본 일정만 성공 응답으로 반환해서는 안 된다.
