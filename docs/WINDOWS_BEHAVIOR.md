# Windows 표시 검증 기록

## 현재 구현

- 기본 창은 테두리가 없고 크기를 조절할 수 있으며, 항상 위는 기본값이 `false`다.
- 헤더를 끌어 이동하고 접기 버튼으로 다음 일정만 보이는 126 논리 픽셀 높이로 줄일 수 있다.
- 닫기 요청은 프로그램 종료 대신 창을 숨긴다. 완전 종료는 트레이의 `종료`를 사용한다.
- 트레이에서 표시/숨기기, 새로고침, 항상 위, 자동 실행, 설정, 로그아웃, 종료를 선택할 수 있다.
- 자동 실행은 사용자가 설정이나 트레이 메뉴에서 선택한 뒤에만 등록한다.
- 단일 실행 플러그인은 두 번째 프로세스를 닫고 기존 창을 표시해 포커스한다.
- 창 상태 플러그인은 위치와 크기를 저장하고 다음 실행 때 복원한다.

프런트엔드는 Windows의 Edge 엔진으로 빌드 결과와 340 × 420 레이아웃을 확인했다. 현재 PC에는 Rust 도구 체인이 없어 Tauri 네이티브 실행과 설치 파일 빌드는 수행하지 못했다. 아래 항목은 구현 완료로 표시하지 않고 Windows 실기기 검증 때 결과를 추가한다.

## Windows 11 x64 실기기 점검표

- [ ] 기본 창이 항상 위가 꺼진 상태에서 다른 일반 창 뒤에 머무는지 확인한다.
- [ ] Win+D와 모든 창 최소화 후의 표시를 각각 확인한다. `alwaysOnTop: false`는 바탕화면 계층 고정을 보장하지 않는다.
- [ ] Explorer를 재시작한 뒤 창과 트레이가 정상 동작하는지 확인한다.
- [ ] 트레이의 표시/숨기기, 새로고침, 항상 위, 자동 실행, 설정, 로그아웃, 종료를 확인한다.
- [ ] 설정에서 자동 실행을 켠 뒤 재로그인하고, 끈 뒤 등록이 제거되는지 확인한다.
- [ ] 두 번째 실행이 기존 창을 표시하고 추가 프로세스를 종료하는지 확인한다.
- [ ] 창 위치와 크기가 재실행 후 복원되는지 확인한다.
- [ ] 모니터 분리 후 위젯이 남은 화면 안으로 복귀하는지 확인한다.
- [ ] 화면 배율 100%, 125%, 150%, 200%에서 글자와 조작 버튼이 잘리지 않는지 확인한다.
- [ ] 앱 제거 후 자동 실행 등록과 사용자별 창 상태가 남는지 확인한다.

바탕화면 고정이 비공식 Explorer 창 계층에 의존할 경우 사용한 Windows API, Explorer 재시작 뒤 복구 동작, 지원 Windows 버전을 이 문서에 추가한다.
